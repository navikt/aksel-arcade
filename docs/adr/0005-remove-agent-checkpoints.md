# Remove Agent session Checkpoints

Aksel Arcade will remove Checkpoints and rollback from Agent sessions rather than keeping a hidden safety history behind Desktop Arcade Agent access. This supersedes ADR-0002's apply-then-review rollback model and the Checkpoint portion of ADR-0003: Agent changes remain consent-gated and validated before mutation, and Desktop Arcade will keep read/write Agent access with all permissions enabled and immediate apply-after-validation rather than introducing staged proposals, granular permission toggles, or read-only access as part of this removal. Once accepted, Agent changes become ordinary Arcade project edits reviewed in the live preview, with safety centered on stopping Agent access instead of restoring Agent-specific snapshots or adding a replacement Agent-specific recovery path. An active Agent session should stop on explicit Arcade project replacement so the same pairing credential does not carry over to a different project without fresh consent: import/open package, load shared project snapshot, reset editor to intro, and load built-in templates/demos count as replacement, while normal edits, renames, viewport/theme changes, panel layout changes, and agent-applied changes do not. Project replacement should revoke credentials automatically before the new project is exposed, without adding a second confirmation beyond any existing replacement confirmation; internally this should use a distinct stop reason such as `project-replaced` for cleanup, logs, and tests, and the human-facing UI should simply return Agent status to inactive inside the Agent menu without a separate notification or new trigger indicator. After any stop, external agents should observe only structured revoked, unauthorized, or out-of-session failures and must get a fresh pairing handoff; this removal should not add push notifications or expose stop reasons over the protocol. Session-state reads should expose active session identity, started-at timestamp, permissions, read scope, command names, and protocol/instructions version only, not change history, rollback availability, stop reasons, or replacement recovery metadata. The Desktop Agent menu and copied Agent instructions should remove Checkpoint and rollback language entirely rather than replacing it with an Agent-specific history placeholder; agent-facing instructions should say accepted changes apply immediately after validation. The mutation command should align with the domain term and become `applyAgentChange` rather than retaining the legacy source-only `applySourceChange` name, and the agent-facing protocol/instructions version should bump because command names and result shapes change. Desktop Arcade should not provide a compatibility shim for old `applySourceChange` calls; stale commands should fail with the normal unsupported-command error. Agent change results should return `changedFields` only and should not keep nullable or deprecated Checkpoint identifiers, echo summaries, or create change records; doing so would preserve a false recovery or history contract. Agent change summaries remain required, but only as human-readable change explanations in the command contract, not as rollback history labels or visible UI history. This removal should not introduce a persisted accepted-change audit log or telemetry stream for Agent changes; redacted technical failure logging can remain for transport diagnostics.
