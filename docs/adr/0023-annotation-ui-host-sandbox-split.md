# Split annotation UI between PreviewPane and sandbox hit-testing

Arcade renders annotation controls, markers, badges, and popovers in the main PreviewPane React tree using Aksel components, while the sandbox iframe handles preview element hit-testing, hover/selection outlines, and geometry messages. Custom annotation CSS is limited to overlay geometry or animation gaps that Aksel components do not provide, and that CSS must use Aksel design tokens. The PRD may be created before visual-spec links exist, but it must explicitly list every annotation element, view, and page state that requires visual specs, including the preview-header controls, hover/selection overlay, add/edit popover, markers/tooltips, Clear all confirmation, and empty/dead-target states. UI implementation work remains blocked until those PRD entries are updated with the required visual specs or links, and implementation tasks must carry the relevant visual-spec links for visual/CSS translation rather than infer visuals from Agentation alone. Interaction behavior, including timing and easing, should stay aligned with Agentation unless an Arcade-specific decision explicitly changes it. Pressing Escape with no annotation popover open exits Annotation mode even though Agentation's visible Exit action is dropped. Annotation mode and Inspect mode are mutually exclusive: enabling either mode immediately disables the other and closes the other mode's popovers or selection UI. Annotation markers and hover/edit affordances are visible only while Annotation mode is on; saved annotations persist when the mode is off and become visible again when the user turns Annotation mode back on. The optional annotation layer in Preview evidence mirrors the visible overlays that normal Annotation mode would show for the requested page and viewport; annotation resources remain the source for full non-dead annotation data. Agentation runs same-document and can colocate toolbar UI with target DOM, but Arcade's preview is sandboxed in an iframe and already uses a host/sandbox message boundary for Inspect mode and Preview evidence. We accept the extra message protocol because it keeps durable annotation state and Aksel UI in Arcade, avoids injecting a second React control surface into user code, and preserves the sandbox as the only place that directly inspects rendered preview elements.
