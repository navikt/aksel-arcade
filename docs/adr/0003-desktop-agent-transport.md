# Desktop Agent transport for agent-enabled Arcade

Aksel Arcade will keep Web Arcade and Desktop Arcade on the same Arcade project model and workspace UX, but Agent sessions are Desktop Arcade-only. Desktop Arcade will expose the existing Agent bridge commands through a swappable same-device Agent transport, with short-lived loopback HTTP JSON-RPC and an Agent pairing credential as the first adapter; the superseded browser-global Agent bridge should be removed entirely rather than kept as a second Desktop surface. Web Arcade will not show Agent UI, initialize Agent runtime, publish a browser-global Agent bridge, or own Web-facing Agent access affordances. Agent UI/runtime modules should load from Desktop-only entry points where practical, while the shared renderer keeps an explicit disabled Web capability boundary; zero Agent strings in a Web bundle is not an acceptance criterion unless separate Web/Desktop bundling already makes it natural. Shared preview infrastructure such as diagnostics may remain available to Web Arcade when it supports normal human review, but Web-facing docs and UI should not describe it as Agent access. Tests and docs for positive Agent access behavior should be Desktop-specific; Web coverage should be limited to negative capability-boundary checks. The Desktop Arcade renderer stays browser-like with desktop capabilities exposed only through narrow preload IPC, so Electron owns local agent connectivity without giving the React app broad Node access; this supersedes the browser-only bridge, while ADR-0005 removes the earlier Checkpoint rollback model and Export/Import packages remain the cross-shell sharing path.
