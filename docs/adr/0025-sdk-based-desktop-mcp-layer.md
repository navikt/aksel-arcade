# SDK-based Desktop MCP layer

Desktop Arcade will rebuild its handwritten Desktop MCP protocol layer on the official TypeScript MCP SDK while preserving the Arcade public MCP contract unless that contract conflicts with the MCP specification. The rebuilt layer targets the SDK's latest supported MCP protocol with version negotiation, keeps the fixed local `http://127.0.0.1:3846/mcp` no-auth endpoint, uses SDK-managed protocol sessions against one active Desktop Arcade project, and preserves existing tool names, resource URIs, guidance entry points, and structured Arcade result semantics where spec-compliant.

The implementation should move current main-process MCP code into TypeScript modules under `desktop/mcp/`, keep renderer-owned active-project behavior in `src/services/desktopMcp*`, and share pure contract constants, schemas, types, and generated compact Aksel MCP catalog data from `src/shared/desktopMcp/`. A tiny CommonJS Electron bootstrap may remain for packaging compatibility, but server setup, Streamable HTTP transport, tools, resources, guidance, capture storage, and typed Desktop MCP IPC routing should live in built TypeScript modules. MCP modules are thin protocol adapters: they own SDK registration, schema validation, result mapping, protocol errors, and tool annotations, while Arcade business behavior remains in renderer/domain services or shared pure helpers.

The server should stay request/response-only in this rebuild: no prompts, no resource subscriptions, and no list-changed notifications. It should add spec-native resource templates while preserving useful concrete resource listings, keep `read_resource` as a tool-only client bridge, define Zod/Standard-Schema input and output schemas for stable structured tools, return domain failures as `tools/call` results with `isError: true`, and reserve JSON-RPC errors for protocol or schema failures. Golden MCP contract tests, the existing Electron smoke flow, MCP Inspector compatibility, HTTP security behavior, and generated catalog drift checks are the acceptance boundary.
