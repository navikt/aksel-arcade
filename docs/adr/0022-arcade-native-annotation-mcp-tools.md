# Use Arcade-native annotation MCP tools

Desktop Arcade exposes annotation MCP behavior with Arcade-native tool names and active-project/page arguments rather than copying Agentation's `agentation_*` session-oriented tool names. The v0.3.0 tool set is `list_annotations`, `watch_annotations`, `acknowledge_annotation`, `resolve_annotation`, `dismiss_annotation`, and `reply_to_annotation`. The tools preserve Agentation-equivalent semantics for pending annotations, acknowledgement, resolution, dismissal, replies, and watching for new work, but Agentation's session concept maps to the active Arcade project because annotations are first-class Arcade project data. Annotation read and watch tools default to the active page, accept an explicit page id, and can opt into project scope for all pages. `list_annotations` defaults to open annotations (`pending` and `acknowledged`) and accepts an explicit status filter for `pending`, `acknowledged`, `resolved`, `dismissed`, or `all`. Mutation tools select annotations by globally unique `annotationId`; they do not require `pageId` because annotation ids are preserved UUIDs in project data. Desktop MCP also exposes all non-dead annotation records, including resolved and dismissed history, through resources such as `arcade://project/annotations` and `arcade://project/pages/{pageId}/annotations`, while tools remain the action surface for watching and mutating status or thread state. `reply_to_annotation` appends an agent thread message without changing status; status transitions are explicit through acknowledge, resolve, and dismiss tools. Acknowledge only updates status, timestamps, and agent actor metadata. Resolve and dismiss mutations record agent actor metadata and timestamps; resolve may add an optional summary thread message, while dismiss requires a reason thread message. Agent-authored metadata uses `agent` unless the Desktop MCP runtime can provide a reliable client or agent name; Arcade should not invent more specific identities. The project manifest exposes page-level open and pending annotation counts, filtering out dead-target annotations. `watch_annotations` returns existing pending annotations immediately; otherwise it copies Agentation's long-poll timing defaults by waiting up to 120 seconds for the first pending annotation and batching for 10 seconds after the first one, with caller-provided caps of 300 seconds and 60 seconds. Watching for work includes pending annotations that become usable again after their target resolves in a later render, not only newly created annotation records. MCP status/reply mutations reject annotations whose targets are currently dead. MCP v0.3.0 does not expose destructive annotation delete or clear tools; deletion and page-level clearing remain human UI actions. We accept the loss of exact tool-name compatibility to keep the Desktop Arcade MCP surface consistent with the existing active-project contract and avoid introducing a second session model.
