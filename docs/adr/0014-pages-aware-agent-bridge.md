# Pages-aware agent bridge

The **Agent bridge** is extended so an **External agent** can read and change a multi-page **Arcade project**, but the page set is mutated through explicit lifecycle operations (create, rename, delete, set start page, select active page) rather than by submitting a whole replacement document. The agent read-state exposes the full pages model — **Global config**, the ordered **Arcade pages** with their stable ids and display names, the **start page**, and the **active page** — and an **Agent change** that edits code targets a specific page id or the Global config. Crucially, the app assigns the frozen `pageNN` ids on creation and returns them to the agent; the agent never chooses an id, it only references ids the app has already minted. Agent multi-page is gated behind the same human-controlled multi-page **Workspace preference**: when the human has not enabled it, the agent works single-page on the first page exactly as the human does, and the **Agent operating instructions** tell it to ask the human to enable multi-page rather than attempting page operations.

We rejected the declarative whole-document alternative (agent submits the entire `{globalConfig, pages[], startPageId}` and the app diffs it) because deletion-by-omission is dangerous with a generative agent: a single forgotten page would silently destroy work, and round-tripping ids through the agent invites violations of the frozen-id invariant (ADR 0012). Explicit operations keep id assignment authoritative in the app, make each structural change individually reviewable under the existing apply-then-review model, and let page CRUD stay under the existing `sourceChanges` permission without inventing a new capability. We gate agents behind the human flag — rather than letting an agent independently opt a project into multi-page — so that a human reviewing the prototype is never surprised by a structure they did not turn on, and so the experimental, local-only posture (ADR 0013) holds uniformly for humans and agents. The costs are a protocol-version bump and a larger command surface to document and maintain; the benefit is that multi-page editing by agents is safe, auditable, and consistent with how humans author the same project.
