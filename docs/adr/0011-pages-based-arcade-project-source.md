# Pages-based Arcade project source

The **Arcade project source** is generalized so it is always a **Global config** plus an ordered set of **Arcade pages**, each holding its own JSX and Hooks, with a designated **start page**. Existing single-page projects migrate losslessly to one page (`page01`, named "Page 1") with an empty Global config; the experimental multi-page **Workspace preference** controls only the page-panel UI and how the source is compiled, not the underlying shape. We chose one canonical structure over bolting optional multi-page data beside the existing top-level `jsxCode`/`hooksCode` fields, because two parallel sources of truth desynchronize the moment a user edits in one mode and toggles the other. The cost is a storage migration and making the transpiler, preview, and persistence pages-aware even when the flag is off; the benefit is that there is exactly one representation of project source to reason about, render, and test.
