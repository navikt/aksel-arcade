# MCP as sole guidance source and Arcade authoring corrections

Three independent agent runs against the Desktop Arcade MCP server each built a multi-step form and hit the same walls: an "invalid hook call" from putting shared `useState` in Global config (which the guidance implied was the home for reusable hooks), surprise that the Preview sandbox blocks `localStorage`, and dead-end lookups after guessing component names like `RadioGroup` or `Alert`. The core loop (`start-here` → manifest → `apply_changes` → diagnostics → `capture_preview_evidence`) was praised. We make the MCP server (`desktop/mcpServer.cjs` + `desktop/mcpGuidanceResources.cjs`) the **single source of truth** for the agent experience and delete the unused legacy in-app Agent bridge — `src/services/agentBridge.ts`, the desktop agent transport/session stack, the `useAgentSession` hook, the `AgentSessionMenu`, and the parity test that forced MCP guidance to mirror it. The MCP path depends on none of it; the one piece of coverage worth keeping — sandbox React render failures surfacing as structured diagnostics — moves onto `arcade://project/diagnostics`.

The defects are guidance, not runtime, problems. Page `hooks` source has its top-level hook calls lifted into the page component, but Global config `hooks` stays at **module scope** and is never lifted, so a top-level `useState` there always throws; the guidance is corrected to say Global config is where you *define* shared hook functions, helpers, and components but never *call* hooks, while per-page state lives in each page's `hooks` tab — and a lightweight diagnostic rewrites React's stable "invalid hook call" message with that Arcade-specific advice at the point of failure. We add **no** custom shared-state primitive: inventing an Arcade-specific state API would be neither simple nor true to Aksel. Since each page is an independently rendered screen with no shared React state, a stateful flow such as a multi-step form is authored as a single page with `useState` plus Aksel's own `Stepper`/`FormProgress`/`FormSummary`, and `goToPage` is reserved for genuinely distinct screens — reconciling prd/0030's "wizard" framing. Component discovery is fixed without growing per-read cost: the `arcade://aksel/catalog` index stays lean and `arcade://aksel/components/{name}` resolution becomes forgiving — resolving aliases (`RadioGroup` → `Radio`), returning replacement breadcrumbs for intentionally hidden roots from `src/data/akselAuthoringPolicy.ts` (`Alert` → `InlineMessage`/`LocalAlert`/`GlobalAlert`, `Modal` → `Dialog`, `Dropdown` → `ActionMenu`), and offering "did you mean" near-matches otherwise. Following ADR 0017's token discipline, the always-on `start-here` only corrects the Global-config line and adds one clause that pages don't share state, while the step-flow pattern, sandbox constraints (no `localStorage`/`sessionStorage`, no external network), and a "read the catalog first" nudge live in the on-demand `authoring-guide`; this supersedes ADR 0017's parity-test note.
